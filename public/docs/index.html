01

What AgentOS Studio does

2 minute read

AgentOS Studio is one desktop app that turns Hermes, your Claude subscription, Qoder, Antigravity, Obsidian and Notion into one engineering fleet. Everything the hermes and claude command lines do in a terminal, Studio does in a window: chat, providers, MCP servers, GitHub, updates and the agents' shared task queue.

  • Your machine is the source of truth. Chats, keys and notes stay on your computer. Hermes keeps conversations and settings; your Obsidian vault holds tasks and memory as Markdown files.
  • Agents work together. Studio ships agentos-hub, a native MCP server built into the same binary, so every agent shares one task queue, typed memory, handoffs and questions to each other.
  • You decide how hands-off it is. From a click on every step to repositories that plan, build, review and merge their own work.

The main areas of the app: Today (what waits on you, what runs and what it costs), Chat, Work (goals, missions, autonomy and prompts), Brain (memory, skills and capabilities), Code (repositories and GitHub) and System (setup, connections, updates, safety and diagnostics).

02

Install and first run

15 minutes

Download the installer for your system from the download page; it always serves the latest release, version 1.2.8. The setup guide walks through every prompt step by step.

  1. Run the installer. The builds are not signed with a paid certificate, so Windows shows Windows protected your PC: click More info, then Run anyway. On macOS, right-click the app in Applications, choose Open, then Open again.
  2. Open the app and go to Setup. Press Set up everything: one admin prompt installs Git, Node.js, the GitHub CLI and Claude Code, then Studio installs Hermes and its plugins, fixes your PATH, creates the vault and connects the hub to every agent and editor it finds.
  3. Finish the sign-ins Studio opens: GitHub, your Claude subscription and a model for Hermes.

A machine with only Hermes is a supported setup. Qoder, Antigravity, Notion and the editors are optional rows.

03

Connect your accounts

3 minute read

Hermes runs on subscriptions and keys: the Claude subscription (a Hermes plugin that drives the Claude Code CLI), Antigravity (a plugin that drives the agy CLI) and API keys such as OpenRouter. Pick the provider and model in System, Providers; keys are saved into Hermes' own .env, and every switch can be checked with a live test turn.

Setup's Can Hermes run right now? card checks each provider every five minutes, without ever reading a token:

  • Signed in: from hermes auth status and claude auth status.
  • Plugin on: Hermes can switch a provider plugin off after errors.
  • Recent failures: usage limits with the reset time the provider gave, sign-in errors and timeouts, read from Hermes' error log.
  • Fallback chain: without a second provider, one usage limit stops all work.

Each problem has a fix button that opens the one command that fixes it, such as claude auth login, hermes auth add antigravity-oauth or hermes fallback add. A provider in use that stops also raises an item in the bell and a Windows notification. Details: Connections.

04

Chat and terminals

2 minute read

Chat talks to Hermes (or Claude Code) bound to any repository. Replies stream with rendered Markdown, code blocks with Copy and Apply to file, and a card for every tool call. Your whole Hermes history is in the sidebar, with rename, delete and export to Obsidian. Organise chats into workspaces and folders; map a folder to a repository and every chat started there runs in it.

The terminal drawer holds real terminals (ConPTY on Windows) for interactive Hermes, the Hermes TUI, Claude Code or your shell, and any chat can be continued in a terminal with one click. More: Chat.

05

Goals and missions

4 minute read

A goal is one sentence of outcome ("add tests for the sync script and release it"). Studio plans it into missions, one per pull request, assigns each to an agent, and checks the result before it calls the goal done.

Every goal has an autonomy level:

  • Watch: the plan waits for your approval and each mission waits for a Start click.
  • Ask on risk (the default): work starts on its own; a merge happens on its own only in repositories on the merge allow list, otherwise Studio asks.
  • Full: merges happen on their own whenever the review and merge gate is clear.

The gate is the same at every level: the reviewer is a different agent from the one that wrote the code, CI must be green with checks present, and the budget must hold. Studio only asks you about a short list of things, such as a goal over its metered budget or a mission blocked after its retry; each question has a safe default and a deadline. The bell lists every question, finished goal and blocked mission. More: Goals.

06

Repositories that keep themselves busy

4 minute read

In Work, Autonomy, Studio lists every git repository it can see. Opt one in and it gets a working plan in the repository itself: docs/agentos/PHASES.md, TASKS.md and REPORT.md. Studio keeps one goal in flight per repository: it writes the plan, finishes the first phase with open tasks (one pull request per task, each ticking its own box and adding a report line), and writes the next phase when the tasks run out.

  1. Pick a level: Full, Ask on risk or Watch, as for goals.
  2. Optionally type a direction, for example "keep the design exactly as it is; update the content only". It is added to every goal for that repository, and the reviewer requests changes on any pull request that breaks it.
  3. Press Opt in. The opt-in is itself a pull request to .agentos/routing.json, merged for you, so it lives with the code and works from any machine.

Autonomy is off until you switch it on, and a machine-wide limit keeps the number of busy repositories sized to your computer. Pause here stops one repository on this machine. A report for each repository is kept in the vault at 01_Projects/Autonomy/. More: Autonomous repositories.

07

Prompts that hand work on

3 minute read

Studio does not replace Claude Code, Antigravity, Qoder, Cursor or Claude Desktop; often the right move is to hand work to one of them. Work, Prompts writes that prompt from what Studio already knows about the project: branch and recent commits, open pull requests, missions, the open phases and tasks, AGENTS.md, the vault's project note and the checks that prove the work. To carry a Hermes session into a new one, choose the session and Studio reads it read-only.

  • Check runs rules with no model: a goal, a finish line, constraints, no secrets, no em or en dashes, a size that suits the receiver.
  • Sharpen and What is unclear? are one quiet Hermes turn each.
  • Hand it over by copying it, writing it into the repository, or putting it on the agents' task queue.

Every prompt is saved with its project, every version is kept, and Refresh context updates only the facts so a prompt saved last week goes out with today's state. More: Prompts.

08

Skills, MCP servers and the hub

3 minute read

Brain, Capabilities is one index of every skill, plugin, agent and MCP server on your machine, from Hermes, Qoder, Claude Code and any folder you add.

  • Skill bridge: open a Qoder or Claude Code skill and press Bridge to Hermes. Studio links it into one folder Hermes reads; it never copies the skill or changes its source, and Hermes' own skills win when names collide.
  • MCP router: one table of every MCP server across Hermes, Claude Code, Qoder and Antigravity, with whether each answers and every tool it exposes. Add servers from a catalog and sync them to every agent.
  • agentos-hub: the shared bus every agent talks to: a task queue, typed memory with ranked recall, agent identities and the registry, handoffs and questions between agents. Claude Desktop, Cursor, VS Code, Windsurf and Codex get it read-only.

More: Capabilities.

09

Safety and spend

2 minute read

  • Permissions: allow, ask or deny per action, enforced in the app's Rust core, with an approval prompt for anything destructive and an audit log.
  • Unattended workers get only the tools their repository allows, and never skip permission checks.
  • Budgets: a metered budget per goal and a global one with a hard stop. Flat subscriptions are not counted; once the metered budget is spent, metered work stops and subscriptions carry on.
  • Pause the fleet in the title bar stops all new work in one click.
  • Constitution: your rules for every agent, synced to every repository and checked on every pull request.
10

Updates

1 minute read

Studio checks itself, Hermes, the Hermes plugins and Claude Code shortly after launch and every three hours (fifteen minutes when a source was unreachable). When a new version of Studio is out, the title bar shows Update to and the version: one click downloads, installs and restarts. Every update is backed up first and can be rolled back. Release notes for each version are on GitHub.

11

When something goes wrong

Reference

An agent hit its usage limit

A flat plan such as the Claude subscription has a usage window. When a worker reports the limit, Studio hands its mission to the next free agent (Claude Code, then Antigravity, then Hermes) and sends new work elsewhere until the limit resets. Add a second provider with hermes fallback add so chat keeps working too.

The network dropped

The status bar shows Offline. Nothing new starts and nothing is marked stuck; work resumes when the network returns. If you run a local model runtime, its models are listed and can be pinned in Providers.

A goal failed

For an opted-in repository, Studio starts a fresh goal for what is left on the next pass, at most twice a day; the finished tasks are already ticked in the repository. Open the goal from Today to see each mission's log.

Something on Setup is red

Open System, Diagnostics. It runs the start-up checks again, shows each result and offers a fix button where one exists. Close and reopen the app after installing a tool by hand.

Windows says the publisher is unknown

Expected: the builds are not signed with a paid certificate. Click More info, then Run anyway. You can check the download against the SHA256SUMS file on the release page.

I need a person

Open an issue at github.com/konethegreat/agentos-studio/issues with what you clicked, what you expected and a screenshot. Diagnostics can copy the logs for you; check them for anything private before you paste. The full guide is Troubleshooting.

12

Where your data lives

1 minute read

Chats and settings are Hermes' own files on your computer. Tasks and memory are Markdown in your Obsidian vault. Studio's own records (workspaces, missions, goals, permissions and the audit log) are one database in your user folder. Keys stay in Hermes' .env, and connection checks never read a token. Nothing is sent anywhere except to the providers and services you connect. More: App privacy.
